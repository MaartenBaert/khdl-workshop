[[reed-solomon-gf-mul]]
=== RsGfMul arithmetic test wrapper

Source: `rtl/reedsolo_gf_mul.kh`. This private module exposes the GF
helpers as combinational ports for exhaustive arithmetic simulation.
`RsEncoder` and `RsDecoder` call `RS` helpers directly; they do not
instantiate this wrapper.

Its only parameter is `RS: type = RsDefault`. All ports are asynchronous
combinational values; there is no clock, reset, valid, ready, or padding.

[cols="1,1,1,3",options="header"]
|===
|Port |Direction |Width |Meaning
|a, b |in |m each |Polynomial-basis field elements.
|long_value |in |2*m-1 |Unreduced polynomial to reduce.
|product |out |m |`RS.gf_mul(a,b)`.
|long_product |out |2*m-1 |`RS.gf_mul_long(a,b)`, before reduction.
|reduced |out |m |`RS.gf_reduce(long_value)`.
|===

Bit `i` represents the coefficient of `x**i` in each port. Outputs follow
combinationally after inputs settle, with zero registered cycles of latency.
This diagram shows settled intervals, not physical propagation delays:

....

....

Python `resolve` can access the private wrapper for verification; it is not
a public cross-file import API. For integration, use `RS.gf_mul` and the
related helpers documented in <<reed-solomon-configuration>>.
