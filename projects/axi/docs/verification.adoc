[[axi-verification]]
== Verification and limits

[[axi-verification-commands]]
=== Commands and tools

From the repository root:

----
.venv/bin/python -m projects.axi.tools.compile --check
.venv/bin/python -m projects.axi.tools.compile
.venv/bin/pytest projects/axi/tests
.venv/bin/python -m projects.axi.tools.formal --target pipeline --unbounded
.venv/bin/python -m projects.axi.tools.formal --target error
.venv/bin/python -m projects.axi.tools.formal --target manager
.venv/bin/python docs/build.py
----

The `--check` run elaborates the concrete profiles in `rtl/channel/examples.kh`,
`rtl/channel/ref_self.kh`, and `rtl/examples/checks.kh`. Without it, the tool also
exports the demonstration modules to `build/axi/verilog/`. `setup.sh` installs
the Python test dependencies, including cocotb 2.x and cocotbext-axi 0.1.x.
Verilator is required; Yosys is required for the formal test and tool, and
ABC with `yosys-witness` makes it faster and enables unbounded proofs. Builds
use ignored paths or pytest temporary directories.

[[axi-channel-verification]]
=== Channel tests

Transaction scoreboards cover different payloads, queue counts, depths, loop
orders, stalls, reset, and module boundaries. Separate method-level tests check
immediate endpoint effects, independent Fifo sides, Internal chaining, peek
behavior, precondition failures, and lifecycle errors. Implementation-specific
tests measure full-rate operation separately from the application correctness
tests. Negative elaboration tests cover binding roles, payload types,
process/reset/clock context, state ownership, and reference escape.

[[axi4-verification]]
=== AXI4 tests

Verification combines native API tests, independent burst arithmetic,
cycle-level scoreboards, adversarial response schedules, and
https://github.com/alexforencich/cocotbext-axi[cocotbext-axi] Manager and RAM
peers. Profiles cover 8/32/64-bit simulated data paths, a 1024-bit
arithmetic/elaboration profile, absent and present optional fields,
non-power-of-two context capacities, Internal/Fifo scheduling, stalls, reset,
errors, and malformed-peer assertions.

Endpoint tests hold an older endpoint outstanding while another repeatedly
fills and reuses a three-slot queue, check separate response buffers and
configured IDs, and enforce global AW/W order while B completion is withheld.
Elaboration tests cover heterogeneous groups, disabled directions, zero-width
IDs, and 1024-bit data. They reject duplicate or out-of-range IDs, runtime IDs,
and incorrect endpoint roles. Private KHDL test facades live under
`tests/rtl/`, outside the production API.

[[axi4-formal]]
=== Formal checks

`tools/formal.py` exports a module, wraps it in a generated harness, and uses
ABC, or Yosys's built-in SAT solver when ABC is not installed, to check every
behavior within a fixed number of cycles after reset. For `AxiPipeline`, ABC's
PDR engine also proves the properties for any number of cycles.
Reset is asserted in the first cycle and is unconstrained afterwards, so
resets during transactions are included. Every KHDL runtime assertion in the
export is also a proof obligation (<<axi-verification-synthesis>>).

The AXI4 rules come from a protocol monitor, `formal/axi4_protocol.sv`, written
from the specification rather than from this implementation. It checks reset
and handshake rules, request legality (burst type, length, size, 4 KiB
boundaries, WRAP alignment, exclusive-access restrictions, and AxCACHE
encodings), WLAST and WSTRB for each beat, W ordering, RID/BID matching,
RLAST, same-ID ordering, and B only after both AW and the final W beat. Rules
for the module under test are assertions. Rules for the other side are
assumptions, so the environment may do anything the specification allows:
W before AW, interleaved reads and reordered responses with different IDs,
narrow, unaligned, FIXED, WRAP, and exclusive bursts, any legal attributes,
and arbitrary stalls.

[options="header",cols="1,2,3"]
|===
|Target |Module under test |Checks
|`pipeline` |`AxiPipeline` |Design contract: each channel delivers exactly its
input beats, in order, with at most two in flight. Stalled outputs stay
stable, and VALID is low in and after reset. Inputs need not be legal AXI.
|`error` |`AxiError` as a Subordinate |Protocol monitor, plus the design
contract that every R and B response is DECERR.
|`manager` |Fixed-ID Manager with two read and two write endpoints (IDs 0 and 1)
|Protocol monitor. Application requests and data are arbitrary within the API
usage contract; the Subordinate's responses are arbitrary within the
specification.
|===

Each target has a negative control that must fail: a corrupted AW payload,
a flipped RLAST, and a reserved AR burst encoding, respectively. For `error`
and `manager`, a reachability run must find a trace with useful progress,
such as a completed multi-beat read, a write response, and interleaved or
early data, which shows that the assumptions are not vacuous.

Apart from the unbounded `AxiPipeline` proof, these are bounded safety checks
of small configurations. They do not show that transactions complete. Long bursts and longer
transaction sequences are covered only up to the checked depth, a few cycles,
because runtime grows steeply with depth. The `manager` target checks the
signals the Manager drives and its own assertions, not that responses reach
the right endpoint. That, `AxiRam` data integrity, the pooled Manager,
`AxiRouter`, and `AxiCopy` have simulation coverage rather than formal checks.
https://github.com/ZipCPU/wb2axip#formal-verification[ZipCPU's public full-AXI4
properties] are a deliberately reduced subset that is not intended to build, and
it assumes that W never precedes AW. The monitor here covers its protocol-rule
categories from the specification instead, except bounded response delays and
exclusive-monitor behavior. See `formal/README.md` for commands, configurations,
depths, and how to read counterexamples.

[[axi-verification-synthesis]]
=== Synthesis and remaining limits

KHDL currently lowers runtime assertions to unguarded printing and `$finish`.
Verilator handles these checks, but Yosys 0.66 rejects `$finish` in an always
block. https://github.com/khdl-lang/khdl/issues/36[khdl#36] contains a minimal reproducer. Real exports need
a compiler or backend synthesis guard before direct Yosys synthesis is usable.
The formal tool therefore preserves the original export and creates an
explicitly named formal-only copy. Each guarded failure task sets a sticky
failure flag that an assertion checks, and only diagnostic text is removed.
Unexpected lowering is rejected, and normal RTL exports are unchanged.

Exploratory Yosys generic-cell experiments, with only those simulation tasks
removed in temporary copies, have compared structures. In an earlier version,
Fifo stages kept combinational paths local between queues. Balanced round-robin
trees were shallower than the linear scan for larger endpoint counts. These comparisons
are not technology mapping, a formal proof, physical timing, or a guarantee for
other configurations. Neither simulation nor the formal checks establish
physical timing or technology-specific area.

The Manager's address arbiters use the linear two-pass scan. The KHDL skill's
`skills/khdl/assets/round_robin.kh` also provides two balanced-tree selectors
with the same result. `tests/test_synthesis_patterns.py` compares all three
against an independent model, both as compile-time calls and in simulation.
The simulations cover 1, 3, 5, 8, 17, 32, and 65 requesters: exhaustively over
request masks and previous winners up to 8, and for larger counts with empty
and full masks, every single-request position, and random masks.

Scratch reference registers remain clearly marked for replacement when mixed
hardware/reference structs are fixed (https://github.com/khdl-lang/khdl/issues/38[khdl#38]). https://github.com/khdl-lang/khdl/issues/35[khdl#35]
records the lack of view-qualified interface reference types; the binding
functions' output-register declarations still reject wrong-direction bindings.
The generic channel examples do not implement AXI transaction semantics. CDC
and general crossbar arbitration remain outside this project.
